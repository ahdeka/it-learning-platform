# 비기능 요구사항

- 상태: 초안
- 수치가 비어 있는 항목은 **Spike(PoC)에서 측정한 뒤** 채운다. 근거 없이 숫자를 정하지 않는다.

## 보안 (SEC)

이 서비스는 **신뢰할 수 없는 사용자에게 실제 리눅스 셸을 준다.** 가장 중요한 요구사항 묶음이다.

### 권한 분리

| ID | 요구사항 | 이유 |
|---|---|---|
| NFR-SEC-001 | Docker 제어 권한(`docker.sock` 접근)은 **runner 프로세스만** 가진다. API 서버는 갖지 않는다 | `docker.sock` 접근은 사실상 호스트 root 권한. API 서버 취약점이 호스트 탈취로 이어지는 것을 막기 위함 ([ADR-0004](../02-architecture/adr/ADR-0004-separate-runner.md)) |
| NFR-SEC-002 | runner는 DB에 직접 접근하지 않는다 (로컬에서도 Docker 네트워크로 분리) | runner가 뚫렸을 때 데이터까지 노출되지 않도록 |

### 사용자 컨테이너 제한

| ID | 요구사항 | 이유 |
|---|---|---|
| NFR-SEC-010 | 메모리 상한 `--memory`, 스왑 금지 (`--memory-swap`을 `--memory`와 같은 값으로) | 메모리 폭주, 스왑으로 인한 서버 전체 저하 방지 |
| NFR-SEC-011 | CPU 상한 `--cpus` | 무한 루프 등으로 다른 사용자와 서버에 영향 주는 것 방지 |
| NFR-SEC-012 | 프로세스 수 상한 `--pids-limit` | 포크 폭탄 방지 |
| NFR-SEC-013 | `--cap-drop=ALL`, `--security-opt no-new-privileges`, 컨테이너 안에서 비 root 사용자로 실행 | 컨테이너 탈출 공격 면적 축소 |
| NFR-SEC-014 | 기본은 **외부 네트워크 차단**. 네트워크가 필요한 문제는 문제 전용 내부 네트워크만 허용 | 실습 컨테이너가 외부 공격의 경유지로 악용되는 것 방지 (호스팅 업체 계정 정지 위험 포함) |
| NFR-SEC-015 | 일부러 취약하게 만든 서비스(해킹 문제)는 다른 사용자 컨테이너, 호스트와 격리된 네트워크에 둔다 | 취약 서비스가 뚫려도 피해가 문제 안에서 끝나도록 |
| NFR-SEC-016 | root 권한이 필요한 문제는 전체 root 대신 범위를 좁힌 sudo를 준다 | 채점 무력화, 탈출 시도 방지 |

### 채점 무결성

| ID | 요구사항 | 이유 |
|---|---|---|
| NFR-SEC-020 | 상태 검사 스크립트는 컨테이너에 미리 넣지 않는다. 제출 시점에 runner가 주입·실행 후 삭제하거나, 컨테이너 밖에서 검사한다 | 사용자가 스크립트를 보고 답을 알거나, `exit 0`으로 고쳐 무조건 정답 처리하는 것 방지 |
| NFR-SEC-021 | 검사는 절대 경로 명령(`/usr/bin/stat` 등)과 사용자가 수정할 수 없는 권한으로 실행한다 | 사용자가 `ls` 등을 가짜 스크립트로 바꿔치기하는 것 방지 |
| NFR-SEC-022 | 플래그는 DB에 **해시로 저장**한다 | DB가 유출돼도 정답이 노출되지 않도록 |

### 웹 / 게스트

| ID | 요구사항 | 이유 |
|---|---|---|
| NFR-SEC-030 | 터미널 WebSocket 연결 시 세션 소유자(게스트/회원)를 검증하고 `Origin` 헤더를 검사한다 | 다른 사람의 터미널에 붙는 것, 크로스 사이트 WebSocket 하이재킹(CSWSH) 방지 |
| NFR-SEC-031 | 게스트 토큰은 추측 불가능한 난수로 만들고, DB에는 해시로 저장한다 | 토큰 탈취·위조 방지 |
| NFR-SEC-032 | 게스트 실행 제한은 게스트 ID와 IP를 함께 기준으로 한다 | 쿠키 삭제만으로 제한을 우회하는 것 방지 |
| NFR-SEC-033 | (공개 전) 봇 차단 수단을 둔다. 후보: Cloudflare Turnstile (무료) | 자동화된 컨테이너 생성 남용 방지 |
| NFR-SEC-034 | 게시판 비회원 비밀번호는 해시로 저장한다 (Later) | 평문 비밀번호 유출 방지 |

## 자원 / 가용성 (RES)

| ID | 요구사항 | 이유 |
|---|---|---|
| NFR-RES-001 | 모든 사용자 컨테이너를 하나의 부모 cgroup 아래에 두고 **합계 메모리 상한**을 건다 (`--cgroup-parent`) | 컨테이너끼리 경쟁해도 API 서버와 DB 몫의 메모리를 보호 |
| NFR-RES-002 | 메모리 부족 시 사용자 컨테이너가 먼저 종료되도록 OOM 우선순위를 조정한다 (`--oom-score-adj`) | OOM Killer가 DB나 API 서버를 죽이는 것 방지 |
| NFR-RES-003 | 대기열에서 작업을 꺼낼 때 **개수가 아니라 실제 여유 메모리**를 기준으로 입장시킨다 | 컨테이너 상한 합이 실제 메모리를 넘는 오버커밋 운영을 안전하게 하기 위함 |
| NFR-RES-004 | 유휴 타임아웃: 일정 시간 입력이 없으면 컨테이너 회수 | 자리만 차지하는 세션 정리 |
| NFR-RES-005 | 최대 실행 시간 제한 | 무한 점유 방지 |
| NFR-RES-006 | 서버 재시작 등으로 생긴 **고아 컨테이너**를 주기적으로 정리한다 | DB 기록과 실제 컨테이너 불일치 방지 |
| NFR-RES-007 | 동시 실행 수, 컨테이너별 상한, 합계 상한, 타임아웃, 게스트 제한은 모두 **설정값**으로 둔다 | 서버 사양에 맞춰 코드 수정 없이 조정 |

## 이식성 / 운영 (OPS)

| ID | 요구사항 | 이유 |
|---|---|---|
| NFR-OPS-001 | 모든 구성요소를 docker-compose로 실행할 수 있다 | 어떤 서버로든 같은 방식으로 배포 |
| NFR-OPS-002 | 이미지를 amd64 / arm64 멀티 아키텍처로 빌드할 수 있게 한다 (`docker buildx`) | ARM 서버(무료 클라우드 등)와 x86 서버 모두 대응 |
| NFR-OPS-003 | 서비스 간 주소, DB 접속 정보 등은 환경변수로 주입한다 | 1대 구성 ↔ 여러 대 구성 전환 시 코드 수정 불필요 |
| NFR-OPS-004 | DB 스키마 변경은 Flyway 마이그레이션으로만 한다 | 변경 이력 추적, 테이블 정의서 작성 근거 |
| NFR-OPS-005 | (배포 시) DB 백업은 서버 밖으로 보관한다 | 서버 장애·침해 시 데이터 보존 |
