## 작성 규칙

### ID 규칙
문서끼리 서로 참조하기 쉽도록, 그리고 나중에 일본식 문서의 번호 체계로 옮기기 쉽도록 ID를 붙입니다.

| 접두사 | 대상 | 예시 |
|---|---|---|
| `FR-` | 기능 요구사항 | FR-TRM-001 |
| `NFR-` | 비기능 요구사항 | NFR-SEC-001 |
| `ADR-` | 기술 결정 기록 | ADR-0004 |
| `S-` | 화면 | S-05 |
| `API-` | API | API-SES-001 |
| `WBS-` | 작업 | WBS-0.5.2 |

### 상태 표기
- **초안**: 논의 중, 언제든 바뀔 수 있음
- **확정**: 합의 완료. 바꾸려면 ADR이나 변경 이력을 남김
- **보류**: 의도적으로 결정을 미룸 (이유를 함께 적음)

### 다이어그램
- 다이어그램은 **Mermaid**로 작성합니다. GitHub과 Notion 양쪽에서 렌더링됩니다.
- 이미지 파일은 Mermaid로 표현할 수 없는 경우에만 사용합니다.

### 변경 원칙
- 코드 변경이 설계에 영향을 주면 **같은 PR/커밋에서 문서도 수정**합니다.
- 기술 선택을 바꿀 때는 기존 ADR을 수정하지 않고, 새 ADR을 만들어 기존 것을 "대체됨(Superseded)"으로 표시합니다.

## 일본식 문서 대응표

나중에 일본식 설계서(Excel)를 작성할 때 어느 문서에서 가져오면 되는지 정리한 표입니다.

| 일본식 문서 | 주요 항목 | 원본 문서 |
|---|---|---|
| **要件定義書** | 背景・目的, 業務要件, 機能要件, 非機能要件 | 기획서, 기능 요구사항, 비기능 요구사항 |
| **基本設計書** (外部設計) | システム構成図, 画面一覧, 画面遷移図, IF一覧, テーブル一覧 | 시스템 구성, ADR, 화면 목록, API 설계, ERD |
| **詳細設計書** (内部設計) | API仕様, テーブル定義書, 処理フロー, クラス設計 | API 상세, ERD/Flyway 스크립트, 시퀀스 다이어그램 |
| **テスト仕様書** | 単体・結合テスト項目 | (구현 단계에서 작성) |
| **WBS / ガントチャート** | 作業項目, 予定・実績 | WBS |

### 용어 대응 (작성 시 참고)

| 한국어 | 日本語 |
