# ADR-0006: 게스트 우선 이용 정책과 actor 모델

- 상태: 확정
- 결정일: 2026-11-04

## 배경

- 회원가입 없이도 즐길 수 있는 부분을 충분히 만들고 싶다 (커뮤니티 포함).
- 듀오링고처럼 첫 방문에 몸풀기 / 실력 테스트를 하고, 결과를 본 뒤 가입을 유도하는 흐름을 원한다.
- 포트폴리오 열람자(면접관 등)는 가입하지 않는다. 핵심 기능을 가입 없이 체험할 수 있어야 한다.
- 수익화 계획이 없으므로 가입자 수 자체를 늘릴 이유는 약하다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 몸풀기 후 가입 강제 | 회원 수 확보, 남용 방지 쉬움 | 포트폴리오 열람자 이탈, "가입 없이 이용" 방향과 불일치 |
| B. 전부 개방 | 진입 장벽 없음 | 가장 비싼 자원(컨테이너)을 익명에게 무제한 개방 |
| C. 게스트도 핵심 기능 이용, 비싼 것·오래 남는 것은 회원 혜택 | 체험과 자원 보호 양립 | 게스트 식별·기록 이전 구현 필요 |

## 결정

**C. 게스트 우선 + 회원 혜택 구조.** 정책 상세는 [기획서 6장](../../00-overview/project-overview.md#6-게스트--회원-정책) 참고.

데이터 모델은 **actor 모델**로 한다.

- 첫 방문 시 게스트 ID를 발급한다 (쿠키).
- 풀이 기록, 테스트 결과 등 모든 기록은 "회원 ID"가 아니라 **actor**에 연결한다.
- actor는 게스트일 수도 회원일 수도 있다.
- 가입 시 게스트 actor의 기록을 회원 actor로 **병합**한다.

## 근거

- 가입 유도를 마케팅이 아닌 **자원 보호 수단**으로 보면 기준이 명확해진다.
- 기록을 처음부터 actor에 연결해 두지 않으면, 나중에 게스트 기능을 넣을 때 테이블 구조를 바꿔야 한다.
- 게스트 → 회원 병합(식별자 설계, 중복 기록 처리, 트랜잭션)은 면접에서 설명하기 좋은 기술 주제다.

## 결과와 영향

- 게스트 실행 제한은 게스트 ID와 IP를 함께 기준으로 한다 (쿠키 삭제 우회 방지).
- 몸풀기 테스트는 컨테이너가 필요 없는 퀴즈형 위주로 구성해, 익명 사용자의 컨테이너 사용을 줄인다.
- 문제 유형에 `QUIZ` / `TERMINAL` 구분이 필요하다.
- 인증 방식 결정 시 게스트와 회원을 같은 방식으로 다루기 쉬운지가 판단 기준 중 하나가 된다 ([ADR-0008](ADR-0008-authentication-deferred.md)).
