# ADR-0002: 모노레포 구조

- 상태: 확정
- 결정일: 2026-11-04

## 배경

backend, runner, frontend, 인프라 설정, 문서를 어떻게 저장소로 나눌지 정해야 한다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 모노레포 (하나의 저장소) | 혼자 관리하기 쉬움, 한 커밋으로 여러 영역 변경, 포트폴리오로 한눈에 보임 | 저장소가 커짐, 빌드 도구가 섞임 |
| B. 영역별 저장소 분리 | 영역별 독립 배포·권한 관리 | 혼자 하기엔 관리 부담, 변경이 여러 저장소에 흩어짐 |

## 결정

**A. 모노레포.**

```
backend/   frontend/   runner/   infra/   docs/
```

## 근거

- 1인 개발에서는 저장소 분리의 이점(팀별 권한, 독립 배포 주기)이 거의 없다.
- API 변경과 프론트 수정, 문서 수정을 한 커밋으로 묶을 수 있다.

## 결과와 영향

- backend와 runner는 각각 독립된 Gradle 프로젝트로 둔다 (공통 코드가 생기면 그때 멀티 모듈 검토).
- 나중에 여러 서버로 배포하더라도 저장소 구조는 바꿀 필요가 없다.
