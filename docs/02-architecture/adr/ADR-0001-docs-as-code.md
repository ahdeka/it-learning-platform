# ADR-0001: 설계 문서는 레포 안 Markdown을 원본으로 한다

- 상태: 확정
- 결정일: 2026-11-04

## 배경

기획서, API 설계서, WBS 등 문서 작업을 체계적으로 하고 싶다. 포트폴리오로 쓸 예정이고, 일본 취업 시장에서도 활용할 수 있도록 일본식 설계서(要件定義書・基本設計書・詳細設計書)도 나중에 작성하고 싶다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. Notion 앱을 원본으로 | 보기 좋음, 편집 편함 | 코드와 버전이 따로 놂, 링크 공유 필요, Markdown으로 내보내기가 깔끔하지 않음 |
| B. 레포 안 Markdown을 원본으로 | 코드와 같은 커밋으로 관리, GitHub에서 바로 보임, Notion으로 가져가기 쉬움 | 편집 UI가 Notion보다 불편 |
| C. 처음부터 일본식 Excel | 일본 SI 현장 방식 그대로 | 변경 이력 추적이 어렵고, 개인 프로젝트 속도에 안 맞음 |

## 결정

**B. 레포 안 `docs/` 폴더의 Markdown을 원본으로 한다.**

- 다이어그램은 Mermaid로 작성한다.
- 일본식 문서는 원본에서 **파생**시킨다. 대응 관계는 [docs/README.md](../../README.md)에 정리한다.

## 근거

- 면접관이 레포 하나만 열면 코드와 설계를 함께 볼 수 있다.
- API를 바꾼 커밋에 설계서 수정이 같이 들어가므로 문서가 코드를 따라가기 쉽다.
- Notion은 Markdown 가져오기를 지원하므로 필요하면 언제든 옮길 수 있다. 반대 방향은 번거롭다.
- 비용: GitHub, Notion 모두 개인 무료 플랜으로 충분하다.

## 결과와 영향

- 문서에 ID 규칙(FR-, NFR-, S-, API- 등)을 둬서 나중에 일본식 문서의 번호 체계로 옮기기 쉽게 한다.
- 일본식 문서 작성 시점은 MVP 이후로 둔다.
