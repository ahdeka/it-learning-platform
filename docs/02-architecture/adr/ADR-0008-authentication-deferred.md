# ADR-0008: 인증 방식 (세션 / JWT)

- 상태: **보류**
- 기록일: 2026-11-04

## 보류 이유

MVP는 게스트만으로 동작하므로 회원 인증이 필요한 시점이 Phase 4 이후다. 회원 기능 착수 전에 결정한다.

## 판단할 때 볼 기준

| 기준 | 세션 (쿠키) | JWT |
|---|---|---|
| 게스트와 회원을 같은 방식으로 다루기 | 쉬움. 게스트도 회원도 같은 쿠키 세션 | 게스트용 토큰 발급 설계가 별도로 필요 |
| 로그아웃 / 강제 만료 | 서버에서 세션 삭제로 즉시 가능 | 만료 전 무효화하려면 블랙리스트 등 추가 장치 필요 |
| 서버 상태 | 세션 저장소 필요 (DB 또는 Spring Session) | 상태 없음 |
| Next.js ↔ Spring 도메인이 다를 때 | 쿠키 도메인·SameSite 설정 주의 | 저장 위치(쿠키 / 메모리)에 따라 XSS·CSRF 대응이 달라짐 |
| WebSocket 인증 | 핸드셰이크 시 쿠키가 자동 전송됨 | 토큰을 쿼리 파라미터나 첫 메시지로 넘기는 설계 필요 |

## 현재 기울기

[ADR-0006](ADR-0006-guest-first-actor-model.md)의 게스트 우선 구조와 터미널 WebSocket을 생각하면 **세션 방식이 조금 더 잘 맞는 편**이다. 단, 확정은 회원 기능 착수 시점에 한다.

## MVP에서의 처리

- 게스트 식별은 인증 방식과 별개로 **게스트 쿠키**로 구현한다.
- 이후 어느 방식을 택하든 게스트 쿠키 → actor 매핑은 유지한다.
