# Spike: 웹 터미널 기술 검증 (Phase 0.5)

- 상태: 계획
- 기간: **1~2주로 고정.** 기간 안에 안 되면 범위를 줄이거나 방식을 바꾼다. 늘리지 않는다.
- 코드 품질: **버려도 되는 코드.** 목적은 "되는가"와 "얼마나 드는가"를 아는 것.

## 1. 왜 먼저 하는가

이 프로젝트의 성패는 "브라우저에서 진짜 리눅스 셸을 안전하게 띄울 수 있는가"에 달려 있다. 게시판이나 회원가입은 막혀도 방법이 많지만, 이 부분은 해보기 전에는 모르는 게 많다. 여기서 나온 결과에 따라 Phase 1 이후 설계가 바뀔 수 있다.

## 2. 범위

### 포함
- 버튼 하나로 컨테이너 생성, 탭을 닫거나 종료하면 삭제
- 브라우저 터미널(xterm.js) ↔ WebSocket ↔ backend ↔ runner ↔ `docker exec`
- 플래그 제출형 판정 1건, 상태 검사형 판정 1건
- 메모리, 기동 시간 측정

### 제외
- 대기열, 게스트 식별, DB 저장
- 화면 디자인
- 자원 제한의 완전한 적용 (단, **기본 제한은 Spike에서도 반드시 건다**. 아래 4장)

## 3. 검증 항목

| # | 항목 | 성공 기준 | 결과 |
|---|---|---|---|
| V1 | runner에서 docker-java로 컨테이너 생성 / 삭제 | 생성 후 `docker ps`에 보이고, 삭제 후 사라짐 | |
| V2 | 브라우저에서 셸 조작 | `ls`, `cd`, `vi` 등 대화형 명령이 정상 동작. 창 크기 변경(resize) 반영 | |
| V3 | 연결 종료 시 정리 | 탭을 닫으면 일정 시간 내 컨테이너 삭제 | |
| V4 | 플래그 판정 | 컨테이너 안에서 찾은 플래그를 제출하면 정답 판정 | |
| V5 | 상태 검사 판정 | 예: `/data/secret.txt` 권한을 600으로 바꾸고 제출하면 정답. 검사 스크립트가 컨테이너에 남지 않음 | |
| V6 | backend ↔ runner 통신 방식 결정 | HTTP + WebSocket 중계로 충분한지 판단 | |

## 4. Spike에서도 지킬 보안 최소선

버려도 되는 코드라도 **실제로 셸을 여는 코드**이므로 다음은 지킨다.

- backend, runner, 터미널 WebSocket 포트는 **`127.0.0.1`에만 바인딩**한다. `0.0.0.0`으로 열면 같은 Wi-Fi의 다른 기기에서 내 PC의 Docker를 조작할 수 있다.
- `docker.sock`은 runner에만 연결한다.
- 사용자 컨테이너 기본 제한: `--memory`, `--memory-swap`(같은 값), `--cpus`, `--pids-limit`, `--cap-drop=ALL`, `--security-opt no-new-privileges`, 비 root 사용자, `--network none`
- 문제 이미지는 직접 만든 것만 쓴다.

## 5. 측정 항목

측정 결과는 [비기능 요구사항](../01-requirements/non-functional-requirements.md)의 "측정 후 채울 수치"에 옮긴다.

| 항목 | 측정 방법 | 결과 |
|---|---|---|
| 기본 셸 컨테이너 메모리 (유휴) | `docker stats` | |
| 기본 셸 컨테이너 메모리 (명령 실행 중) | `docker stats` | |
| 서비스 포함 컨테이너 메모리 (예: nginx) | `docker stats` | |
| backend / runner / PostgreSQL / frontend 상시 메모리 | `docker stats` 또는 OS 도구 | |
| 실습 시작 클릭 → 셸 프롬프트 표시까지 시간 | 브라우저 개발자 도구, 로그 타임스탬프 | |
| 컨테이너 10개 동시 생성 시 소요 시간과 메모리 합계 | 스크립트로 반복 생성 | |

## 6. 결과 정리 양식

Spike가 끝나면 이 문서 아래에 다음을 기록한다.

- 검증 항목별 결과 (성공 / 실패 / 부분 성공)
- 측정값
- 예상과 달랐던 점
- Phase 1 이후 설계에 반영할 사항
- 새로 만들 ADR (예: backend ↔ runner 통신 방식, runner 구현 형태)
